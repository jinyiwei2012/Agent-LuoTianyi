# v0.4.0 电话功能开发计划

> 生成日期：2026-08-03
> 前置文档：`docs/PRDs/v0.4.0-电话功能.md`（产品语义）、`docs/dev/v0.4.0-电话功能设计.md`（实现级设计，文件变更清单与实施顺序以此为准）
> 本文档定位：基于当前代码实际完成度，列出剩余工作的具体改动清单与可行性评估。

## 1. 结论摘要

- 服务端初版代码已提交但**处于「待审阅」状态**（git 8a1cb8c `feat: 初步更新打电话功能，待审阅`、8801e4b `refactor: 枚举化实时对话事件类型`）。
- App 端主体已完成（UI、状态机、transport、原生 PCM 模块、Live2D 音频接口）；**缺测试与真机验证**。
- **PC 客户端为零实现**，是剩余工作中最大的一块。
- 服务端测试覆盖远低于设计文档计划（1/11 个测试文件）。
- 总可行性：**高**。无技术路线风险，剩余工作 = 审阅定稿 → 补测试 → PC 客户端 → 端到端验收。

## 3. 实施计划与具体改动

### 阶段 0：服务端代码审阅与协议定稿（P0，最高优先）

**目标**：把 8a1cb8c 的初版代码审阅、修复、合入，冻结 `/call_ws` 事件契约，防止在未定稿协议上叠加改动。

**具体改动**：
- 审阅 `server/src/chat_session/call_stream.py`、`call_stream_manager.py`、`call_settlement.py`、`call_context_builder.py`、`call_memory_pool.py`、`call_response_parser.py`、`call_models.py` 与 `server/src/utils/realtime_dialogue/` 全部文件。
- 审阅要点对照设计文档：状态机迁移走 `_transition(expected, target)`、2 秒接听时序、5 秒重连保留、5 路并发临界区、`CALL_IN_PROGRESS` 聊天互斥、ACK 幂等 `(call_id, response_id, audio_id)`。
- 发现问题直接修复；修复后跑通现有 `pytest tests/test_call_foundation.py` + 全量回归。

**可行性**：高。代码已在仓库，工作量为纯审阅与局部修复。

### 阶段 1：服务端测试补齐（P0）

**目标**：按设计文档 18.1 的清单补齐 10 个缺失测试文件（当前仅 test_call_foundation.py）。

**具体改动**（新增到 `server/tests/`）：

| 文件 | 覆盖 | 可行性 |
| --- | --- | --- |
| `test_call_stream_manager.py` | 5 路并发、第 6 路 -5、同用户互斥、5 秒 resume、超时释放 | 高（纯内存单测） |
| `test_call_stream_state.py` | 合法/非法状态迁移、接通前挂断、重复 end 幂等 | 高 |
| `test_call_protocol.py` | auth、事件 payload、ACK、chat CALL_IN_PROGRESS 拒绝 | 高 |
| `test_realtime_dialogue_qwen.py` | 事件映射、cancel、tool output、usage、错误脱敏（fake WebSocket） | 高 |
| `test_call_context_builder.py` | 人设/画像/偏好拼接、10 分钟/20 条、图片/唱歌/CALL 格式化、排除 summary | 中（依赖 memory/数据库 fixture） |
| `test_call_response_parser.py` | 换行、尾行 flush、语气兜底、function call 分流、cancel 丢弃 | 高（纯函数） |

### 阶段 2：PC 客户端电话功能（P0，最大工作量）

**目标**：PySide6 客户端接入同一 `/call_ws` 协议，实现采集→通话→播放→ACK 闭环。

**具体改动**：

| 文件 | 动作 | 改动内容 | 可行性 |
| --- | --- | --- | --- |
| `client/src/network/call_ws_transport.py` | 新增 | `/call_ws` 连接、user_auth 鉴权、10 秒心跳、5 秒重连保留 + `call.resume`、`server_ack` 解析（读 `payload.ok`）、事件收发 | 高（协议已由 App 端 `call_transport.ts` 验证过） |
| `client/src/network/event_types.py` | 修改 | 增加 `call.start/resume/audio.append/hangup/playback_completed/playback_stopped` 事件常量与 payload 类型 | 高 |
| `client/src/message_process/call_audio_controller.py` | 新增 | PyAudio 采集 16-bit/16kHz/mono PCM → Base64 分帧发送；播放队列严格 FIFO；`stop_playback` 立即停止并回传 ACK；迟到音频丢弃 | 中（PyAudio 已在 `client/setup/requirements.txt`；线程模型需与 Qt 事件循环协调） |
| `client/src/gui/call_dialog.py` | 新增 | 独立全屏/最大化通话窗口：Live2D、请求中/通话中/重连中/结束状态、计时（从 connected_at 起）、红色挂断按钮、耳机提示 | 高（复用现有 live2d_interface.py 与 chat_bubble 模式） |
| `client/src/gui/main_ui.py` | 修改 | 工具栏增加电话入口；通话期间禁用聊天输入与发送 | 高 |

**可行性**：高。无新第三方依赖（PyAudio 已具备）；Live2D 已有 Python 接口；协议与 App 端完全一致，可对照 `app/utils/call_transport.ts` 实现。

### 阶段 3：App 端收尾（P1）

**具体改动**：
- `app/utils/pcm_recorder.ts`：将 `modules/pcm-recorder/` 原生模块的 JS 监听封装独立成文件（或确认现有 index.ts 已覆盖，二选一，保持与设计文档一致）。
- `app/__tests__/` 新增 4 个测试：`call_ws_transport.test.ts`、`call_audio_controller.test.ts`、`useCallLogic.test.tsx`、`call_screen.test.tsx`（`npx jest` 运行）。
- 真机验证：PCM16/16kHz/mono 格式、耳机双向通话、连续 10 分钟、切后台、5 秒内重连、打断停止、Release APK 内 live2d.html 镜像一致。

**可行性**：高。功能主体已存在，剩余为封装收尾与验证。

### 阶段 4：端到端验收（P0 发布门槛，设计文档第 20 节）

**具体改动**：
- `server/scripts/call_load_test.py` 新增：fake provider / 录制事件驱动 5 电话流 + 1 聊天流压测，输出 TTS 最大并发、流内顺序、聊天排队时间、connect/首包/打断 P95、call/conversation 一致率。
- 真实 Qwen 契约 smoke test：带 `QWEN_API_KEY` 手工验证 ASR、server VAD、文本输出、Function Calling、`response.cancel`、上下文增删或 adapter 等价实现。
- 逐项验收设计文档第 20 节 7 项门槛（Qwen 契约 / PCM 格式与 Base64 脱敏 / 打断 P95<1s / 打断句不落库 / 5+1 并发 TTS=1 / 退出码规则 / Release APK Live2D）。

**可行性**：中。依赖真实 Qwen + GPT-SoVITS 环境与真机；是唯一需要外部资源协调的阶段。

### 阶段 5：控制台通话记录页面（P2）

**具体改动**：
- `server/admin_ui/src/main.tsx` 修改：新增通话记录菜单，展示摘要、状态、退出码、后处理状态（P0 不返回完整 transcript，API 已就绪）。
- `server/admin_ui/src/styles.css` 修改：表格与状态徽标。
- 改完执行 `npm run build`，提交 `admin_static/` 产物。

**可行性**：高。API 已实现，纯前端增量。
