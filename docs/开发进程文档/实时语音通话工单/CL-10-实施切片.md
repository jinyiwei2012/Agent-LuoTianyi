## 当前 partial 范围

- 新增 `call_sessions` SQLAlchemy 表，字段严格等于 spec 的持久化 allowlist，并为负时长、负维护序号增加数据库约束。
- 新增 `SqlCallSessionRepository`：原子 create 幂等、请求/呼叫身份冲突拒绝、单语句 expected-state CAS、非终态 stale 查询、owner 范围删除和 SQLite 重开恢复。
- 新增独立 summary / maintenance settlement CAS：各 lane 只更新自己的 status 与 `conversation_id` 或 `maintenance_turn_seq`，并以原子最大值推进共享 `updated_at`；并行完成不会整行互相覆盖。失败 lane 可显式重试为成功，成功 lane 不可回退。通用 lifecycle update 禁止修改 settlement 字段。
- create 冲突同时检查 request 与 call ID 两个 unique identity；二者命中不同既有记录时稳定拒绝，不能错误返回 request winner。
- SQL 与 fake 共享 `STALE_RECOVERABLE_STATES`，调用方请求 terminal state 时也只返回可恢复的非终态记录。
- 呼叫账本的公开 datetime 与 stale cutoff 全部要求 timezone-aware；任意 offset 显式归一化到固定 UTC+8 北京边界，SQLite 内部保存 naive Beijing，读取时附回固定 `+08:00`。禁止依赖宿主时区或把 naive 值交给 `astimezone()` 猜测。
- 时间约束只作用于新呼叫账本接口，不修改 CL-2 或其他 legacy naive datetime 接口；未来 Stage 调用方必须在边界显式转换。
- 最后 bounded remediation 后 CL-10a 定向 ledger 测试 81 passed；persistence integration 扩大回归 131 passed、2 skipped。Black、Ruff、架构边界与 diff check 通过。本轮将 lifecycle CAS 改为严格时间前进，并为完全相同 lifecycle payload 提供不受独立 settlement 字段影响的幂等重试；同一时间不同 payload 不得连续成功。Oracle 3/3 历史仍为 BLOCKED，本文不宣称阶段 gate、人类审核或完整 CL-10 已通过。

## Gate I A1 consumer 候选

- 新增 `CallSettlementConsumerImpl`：读取 `ENDED` durable identity，使用真实 Agent `handle_stimulus` 形成 summary/maintenance actions，再分别通过真实 `realize_action_plan` 执行；Application 只编排，不直接调用 LLM 或 MemoryWriter。
- 新增 call-only `CallSummarySkill`：只消费 immutable final snapshot 中 `COMPLETED` formal turns；无有效轮次使用固定 empty 文本，模型失败或超过 200 字最多重试一次后使用固定 fallback。
- 新增 call-only `CallMaintenanceSkill`：仅消费 `maintenance_turn_seq` 之后的 `COMPLETED` formal turns，provisional、base chat seed、未回复/失败/打断轮次不进入候选；候选和完整 profile 在首次模型成功后冻结，partial write 重试不再次调用模型，候选稳定 ID 复用 CL-1 `MemoryWriter.write_maintenance_candidates`。
- summary 与 maintenance 作为独立 async lane 并行执行，各自只更新自己的 ledger CAS；一条失败不取消另一条。maintenance 只有 memory/profile 全部成功后才推进 turn seq，失败保持旧进度。
- `CallContent` 使用固定主仓库 UUIDv5 namespace，Conversation 为 `source=user/type=call/requested_at naive Beijing`；same UUID 同内容幂等，内容或 owner 冲突拒绝。Agent 内容包含 summary，HTTP history 根据 metadata 只返回 outcome/duration 展示，不返回 summary。
- 当前 consumer 未接 `server_runtime` / endpoint；startup stale recovery、完整账户 reset、metrics 留给 A2/B。无 durable manifest 保存逐轮输入；重启后没有 immutable snapshot 输入时不重建转录或模型输入。

## Gate I remediation 1/3

- summary/maintenance 模型输入保留所有已完成用户轮次；只有 `COMPLETED` 且有 formal text 的角色回复会进入输入。NOT_STARTED/FAILED/INTERRUPTED 仍保留 user semantic，但不附加角色 partial text；provisional 从未进入 final snapshot。
- summary 在调用模型前按 stable Conversation UUID 查询已提交 winner；owner/character/call/outcome/duration/reason 必须与 ledger 一致。已有 winner 直接修复 summary CAS，不重调模型；并发 loser 在写冲突后回读 winner，不覆盖旧事实、不重复计数。
- AC-17 原文允许长期保存“成功提取的向量记忆和用户画像”，同时明确禁止“用户逐字转写、声音描述、情绪、Agent 逐轮回复和通话工作摘要”。据此新增 call-specific frozen batch，只保存最终长期 memory 候选的 type/content/index、完整 proposed profile、稳定 maintenance ID、身份范围与 status/timestamps；不保存 user semantic、formal reply、transcript、snapshot、模型输入、working summary 或 PCM。
- coordinator timeout 使用 shield + owned task 收束：15 秒不续期；取消后等待 consumer/context/to_thread 清理完成才释放 recall pool。该清理可能超过 15 秒，不能当作严格响应 SLA。新模型/新写入是否在 deadline 后启动由外层 task cancellation 和 Agent cancellation boundary 阻止；已进入 owned SQL/vector 操作会完成并按真实结果结算。
- 缺少 `agent.call_summary` 时 AgentRuntime 不注册空模块，普通 chat 启动不受影响；真正进入 call settlement 时稳定报告 capability unavailable。新增 `call_summary_prompt.json` 规定第三人称、中性、≤200 字及事实/情绪/约定/未决约束。
- CANCELLED_BEFORE_ANSWER/DECLINED 直接生成 summary=None 的 CallContent，不调用 Agent/summary model，maintenance turn seq 不推进。

## Gate I remediation 2/3

- 新增 `call_maintenance_batches` durable repository：唯一键 `(call_id,user_id,character_id,previous_turn_seq,target_turn_seq)`，并发 create-or-load 只保留一个 winner；跨 Skill 实例先加载 winner 后才允许模型生成。stable maintenance ID/candidates/profile 可恢复 canonical memory/vector/profile 写入，ledger CAS 失败后重试不重新生成模型结果；提供 `delete_by_user` 供 reset/A2。
- frozen batch 隐私 allowlist 只包含最终长期结果，不包含生成这些结果的原始通话事实。canonical memory 正本仍写入 `agent_memory_records`；batch 标记 completed 只在 maintenance ledger CAS 成功后执行。
- Conversation winner 校验补齐 stable UUID、user/character、source/type、requested_at naive Beijing、`CallContent.render_for_agent()` 与完整 metadata key/value；非法 winner 拒绝推进 summary CAS。
- connected summary 已有 winner 时跳过 summary model；缺少 summary model 时由 `CallSummarySkill` 使用固定失败概要完成 summary lane，不拖普通 Runtime。生产 config 新增专属 `call_summary_prompt` 绑定；配置缺失仍保持普通 chat 可启动。
- Coordinator 固定 15 秒业务 deadline，timeout 后 cancel + join consumer，再释放 recall pool；已启动 owned SQL/vector 写会安全收束。cleanup 可能超过 15 秒，不宣称硬响应 SLA。
- remediation 2 当前验证：settlement/domain/runtime/frozen-batch 定向 **161 passed**；persistence/application/CallStage 扩大回归 **194 passed、2 skipped**；Black、Ruff、architecture B1–B10 与 diff check 通过。Gate I attempt 2 保持 BLOCKED，等待父流程最后 gate 3。

## Gate I remediation 3/3

- 所有 call maintenance batch load/create-or-load/mark-completed 与 canonical memory/vector/link 写入均走 `complete_owned(asyncio.to_thread(...))`。Coordinator timeout 后取消并 join consumer，已启动 repo/vector 操作完成后才释放 pool/batch refs；deadline 后不会启动下一 candidate/write。安全收束可超过 15 秒，不称为硬 SLA。
- 呼叫账本新增 nullable `settlement_input_digest` 技术字段，旧 SQLite 通过 PRAGMA additive migration 只新增该列。digest 是 final snapshot canonical serialization 的 SHA-256：包含 call/terminal identity、北京时区规范 ended_at、maintenance progress、严格有序 turns 的 semantic/status/formal text；数据库只保存 hash，不保存原文或 JSON，也不把 hash 描述为匿名化内容。
- Consumer 在模型、Conversation、memory/profile 写入前原子 claim digest：同 digest 幂等，不同 digest 稳定 `SETTLEMENT_INPUT_CONFLICT`，两条 settlement lane 共用同一 fence。maintenance batch 同时保存 digest，禁止同 call/range 跨 snapshot 静默复用。
- 若 maintenance ledger 已 SUCCEEDED 而 batch 仍 frozen，consumer 在 early return 前只对同 owner/call、`target_turn_seq <= ledger progress` 且 digest 相同的 batch 执行 completed reconcile；不标记其他 batch或超进度 batch。
- `ConversationService.get_call_conversation` 现在强制 user/character scope；UUID 存在但 owner/character/type 不匹配时抛稳定 identity conflict，不返回 None、不覆盖、不推进 summary。
- remediation 3 当前验证：digest/frozen-batch/Agent/application/runtime 定向 **197 passed**；persistence/application/CallStage 扩大回归 **199 passed、2 skipped**；Black、Ruff、architecture B1–B10 与 diff check 通过。历史 Gate I attempt 3 仍为 BLOCKED，等待父流程独立 focused verification。
- 最后 migration-gap bounded 修复：旧 `call_maintenance_batches` 使用 PRAGMA additive migration 增加 nullable digest 列；历史行保持 NULL，不回填、猜测或删除。Repository 读取历史 NULL 行时返回稳定 `LEGACY_CALL_MAINTENANCE_DIGEST_UNAVAILABLE` 并对该 call maintenance fail closed；空旧表迁移后可正常写入新 strict 64-hex batch，fresh batch contract 不允许空/非法 digest。补充 coordinator→owned blocking batch-create 证据，timeout 后资源保持，thread 完成后才释放。
- 阶段保存前具名验证：六个 settlement 新测试文件（migration/batches/consumer/coordinator/owned writes/skills）**23 passed**；三个 domain/repository 契约文件 **160 passed**；AgentRuntime/Agent/coherent 相关 **27 passed**。独立 approved focused probe 为 **50 checks / 0 failed**，连续两次；此前 exp6 的四项 known blockers 与 migration root 均记录为 Fixed。Black、Ruff、architecture B1–B10、diff check 通过。以上是隔离候选证据，不改变历史 Oracle 1/2/3 BLOCKED，也不代表人工验收。
