## 2. v0.4.0 电话功能 —— 服务端初版待审阅，PC 客户端是最大缺口

### 服务端已具备（骨架完整）
- `/call_ws` WebSocket 接口已注册（`server_main.py:178`），与 `/chat_ws` 分离，符合 PRD 第 7.1 节。
- `chat_session/` 下：`call_stream.py`、`call_stream_manager.py`、`call_context_builder.py`、`call_memory_pool.py`、`call_models.py`、`call_response_parser.py`、`call_settlement.py` —— 覆盖状态机、记忆池、行解析、结算等 PRD 核心设计。
- `utils/realtime_dialogue/`：Qwen Audio Realtime 适配层，符合 PRD 第 15 节「模型通信基础设施，不作为 capability 注册」的边界。
- `system/database/call_store.py`：通话表与逐轮记录（幂等结算已有测试覆盖）。
- `chat_session/dependency/global_speaking_worker.py`：流内 FIFO / 流间调度重构已存在（PRD 第 11 节）。
- `config/config.json` 已配置 `realtime_dialogue_service`（`qwen-audio-3.0-realtime-flash`，PCM 16k 输入）。
- 测试：`tests/test_call_foundation.py` 7 项基础单测（行解析与默认语气、记忆池注入/淘汰、退出码契约、Qwen 事件归一化、上下文适配器、结算与 turn 写入幂等），均不依赖外部服务。

### App 端
- `app/app/call.tsx` 存在（约 5KB，基础电话界面）。

### 缺口
1. **PC 客户端（PySide6）完全没有电话支持**：`client/src/` 无任何 call/电话相关代码（无 `call_ws`、无音频采集、无电话界面）。PRD P0 明确要求 PC + App 双端，这是当前最大的未实现部分。
2. **服务端初版未合入正式功能**：git 最新两条相关提交为 `feat: 初步更新打电话功能，待审阅`（8a1cb8c）与 `refactor: 枚举化实时对话事件类型`（8801e4b），代码状态为「待审阅」，需要代码评审与修复。
3. **缺少端到端验证**：现有测试全部为不依赖外部服务的单元测试；PRD 第 18.2 节的性能验收（P95 延迟、5 路并发、TTS 并发=1、结算一致率 100%）均需真实 Qwen + GPT-SoVITS 环境实测。
4. **客户端音频链路未验证**：PCM 采集/重采样、Base64 传输、播放 ACK、打断停止播放均未在真实客户端实现或验证。

### 风险提示（PRD 第 19 节 + 现状）
- 无 AEC：P0 必须提示使用耳机，否则外放回声会误触发打断。
- GPT-SoVITS 全局串行：电话会显著增加持续 TTS 压力，调度器重构质量直接决定聊天与电话是否互相饥饿。
- ACK 是 transcript、memory_write、主动话题计时的共同依据，需防丢失与迟到事件。
- 打断无法真正停止底层推理，GPU 资源可能被取消任务短暂占用。

### 可行性结论
**高**。服务端骨架与 PRD 设计高度吻合，剩余工作集中在三块：① 审阅并完善服务端初版代码；② 实现 PC 客户端电话链路（采集 → `/call_ws` → 播放 ACK）；③ 真实环境端到端验收。无技术路线风险，主要是工作量与联调成本。

## 5. 跨 PRD 依赖与共性风险

1. **TTS 调度器是共享关键路径**：`GlobalSpeakingWorker` 同时服务聊天与电话，其重构质量影响两个 PRD 的体验；电话上线前必须完成 5 路并发 + 1 路聊天的调度验收。
2. **动态可见性隔离**：用户评论仅本人可见，服务端查询必须严格过滤，防隐私泄露；建议沿用现有动态测试并补充越权用例。
3. **聊天/电话互斥**：电话期间拒绝聊天 ingress（`CALL_IN_PROGRESS`），需服务端与双端客户端同时强制。
4. **测试策略局限**：仓库测试均为不依赖外部服务的单元测试（`--run-real-llm` 默认跳过）。电话功能的延迟、并发、结算一致率指标必须依赖真实 Qwen / GPT-SoVITS 环境，建议尽早搭建可重复的联调环境。
5. **代码状态**：最近两次电话相关提交处于「待审阅」，任何新开发前应先完成对 8a1cb8c 的评审，避免在未定稿的协议上叠加改动。
